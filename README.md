# AstroRegolith

An open database and reanalysis for **plant growth in regolith** — lunar, Martian and
asteroid. It gathers the imagery, substrate measurements and transcriptomes that already
exist across NASA's open repositories, joins them where they can be joined, and ships the
analysis, a static web database, and a manuscript describing the result.

> **Live site:** `https://dr-richard-barker.github.io/AstroRegolith/`

The central finding is a linkage. NASA's OSD-476 grew *Arabidopsis thaliana* in 900 mg of
Apollo 11, 12 and 17 regolith against a JSC-1A simulant control, and its deposited
metadata keys **each RNA-seq sample to a growth plate and a twelve-timepoint leaf-count
trajectory**. That makes it possible to ask which genes track *how well an individual
plant grew*, rather than only which regolith it grew in — a covariate that varies by more
than two orders of magnitude inside the regolith-grown plants alone.

| | |
| --- | --- |
| Regolith studies catalogued | 9 in NASA OSDR, 6 curated in NASA PSI |
| Studies with plant imagery | 2 (OSD-476, OSD-670) — 83 images |
| RNA-seq samples joined to a growth trajectory | 16 of 20 (12 one-to-one, 4 plate-mean) |
| Independent phenotype layers | leaf counts (ISA-Tab) and PlantCV shape traits — Spearman ρ = 0.84 |
| Genes correlated with leaf rate at 5% FDR | 2,008 (395 within the Apollo samples alone) |
| Genes replicating in both analyses | 299, of which **82 are invisible to the published substrate contrasts** |

## What is here

```

scripts/        every acquisition and analysis step, numbered; run_all.sh runs them all

results/        derived tables, figures and enrichment — all regenerated by the scripts
```

## The site

Eight views, all reading data committed to this repository:

- **Images** — Apollo-regolith plate scans, asteroid-simulant crop photographs and
  community contributions, with in-browser ArUco marker detection recovering mm-per-pixel
  scale and a 15-chip colour correction.
- **Substrates** — soil-probe response of eight candidate substrates while watering, the
  LHS-1 simulant specification, and LHS-1 against Chang'e-5 returned mare soil.
- **Studies** — the regolith slice of OSDR and PSI, each with a note on *why* it belongs
  in a regolith database.
- **Transcriptomics** — OSD-476 differential expression, both site-by-site and pooled
  (the Broad Lunar model, 21,594 genes), plus GO-slim enrichment.
- **Phenotype ↔ Expression** — the linkage: growth trajectories, how the join is made,
  and the growth-correlated genes.
- **Plan an experiment** — power estimates from the observed effect sizes, five failure
  modes visible in the existing record, and the metadata that decides reusability.
- **Share your data** — the Epicollect5 contribution workflow and a ready-to-build form.
- **Datasets / Export / About** — provenance, citation, and manifest export.

### Why the dashboards read pre-baked JSON

Neither NASA API is callable from a browser on another origin. OSDR answers
`Access-Control-Allow-Origin: osdr.nasa.gov`, its biodata API sends no CORS header at
all, and PSI runs the same GeoDE backend. The scripts harvest those APIs offline and
write JSON into `public/data/`, which the site reads. Every figure on the site therefore
has a committed table behind it and cannot drift from the numbers.

## Reproducing everything

```bash
pip install -r requirements.txt
bash scripts/run_all.sh          # ~10 min on a cold cache, mostly downloads
```

| Step | Does |
| --- | --- |
| `00_fetch_awg_data.py` | primary data from the precursor repository |
| `01_fetch_osdr.py` | OSDR regolith catalogue + OSD-476 ISA-Tab and expression tables |
| `02_fetch_psi.py` | NASA PSI investigation catalogue |
| `03_build_phenotype_table.py` | tidy leaf counts and PlantCV traits; unit and date checks |
| `04_link_phenotype_transcriptome.py` | the sample→plant join, with assertions |
| `05_expression_vs_growth.py` | Spearman correlation of expression against six growth covariates |
| `06_enrichment.py` | GO-slim over-representation |
| `07_substrate_traits.py` | substrate probe, simulant spec and lunar-soil chemistry |
| `08_figures.py` | every manuscript and site figure |
| `09_export_site_data.py` | the JSON the site reads |
| `10_bundle_images.py` | web-sized copies of the imagery OSDR cannot serve cross-origin |
| `11_port_legacy_narrative.py` | the `legacy/` port |
| `12_supplementary_tables.py` | manuscript supplementary tables |
| `13_manifest.py` | `MANIFEST.tsv` and `CHECKSUMS.sha256` |
| `check_references.py` | builds `references.bib` from Crossref, by DOI |
| `check_citations.py` | every `\cite` resolves against the bibliography |

Steps 00–02 and 10 hit the network and are idempotent — a file already present is not
re-downloaded. Steps 03–09 are pure functions of `data/`, so re-runs are byte-stable.
`SKIP_FETCH=1 bash scripts/run_all.sh` reuses what is already downloaded.

## Developing the site

```bash
npm install
npm run dev      # http://localhost:5173
npm run lint     # tsc --noEmit
npm run build    # static output in dist/, base path /AstroRegolith/
```

Deploys to GitHub Pages on push to `main` via `.github/workflows/deploy.yml`.

## The manuscript

```bash
make -C manuscript          # manuscript_npj.pdf
make -C manuscript check    # citation/bibliography cross-check
```

Written for *npj Microgravity*. Every Results value is read from a table in `results/`,
and `references.bib` is generated from Crossref by DOI — the script fails the build on an
unresolved DOI, so no citation is written from memory. See [manuscript/BUILD.md](manuscript/BUILD.md).

## Contributing data

Photograph your plant beside a calibration marker, record the substrate fields that
actually decide reusability — simulant name, supplier **batch**, blend ratio, particle
size, pre-treatment — and submit through the free Epicollect5 app. Days after sowing and
leaf count are asked for in the form deliberately, because they match OSD-476's own
metadata and let your series be plotted against the Apollo plants. The "Share your data"
page walks through it; [CONTRIBUTING.md](CONTRIBUTING.md) covers code and data
contributions.
